# Glowstr Live

Glowstr Live is the first XMR-native livestreaming MVP for Glowstr.

## MVP

- NIP-98 creator login.
- OBS RTMP ingest through MediaMTX.
- MediaMTX publish authentication with a per-stream random key.
- HLS / LL-HLS browser playback.
- NIP-53 `kind:30311` live stream events.
- NIP-53 `kind:1311` signed public live chat.
- XMR tip invoices through the existing Glowstr Commerce/view-only-wallet stack.
- Server-side XMR confirmation watcher.
- Stream goals and confirmed-tip totals.

NIP-53 remains standard. XMR tips are a Glowstr application layer; they are not presented as NIP-57 Lightning zaps.

## Security model

The Live service never stores a Nostr private key. Creators sign NIP-98 and NIP-53 events in their client signer.

Stream keys are stored only as SHA-256 hashes. Creating or rotating a stream key reveals the plaintext once.

The Live service talks to Commerce through the private Podman network with the Commerce admin token. The browser receives only a one-invoice capability token generated by Live.

The current MVP uses the single dedicated receiving/view-only Monero wallet configured for Glowstr Commerce. This is suitable for a single creator/operator deployment. A multi-creator release should add one isolated payment account/view wallet per creator or another non-custodial payout design before opening public creator registration.

## OBS

For a deployment at `live.example.com`:

- Server: `rtmp://live.example.com:1935/live`
- Stream key: displayed once by the creator dashboard, for example `<stream-id>?token=<secret>`

The first MVP uses plain RTMP ingest. Do not expose a reusable stream key over an untrusted network without adding RTMPS, SRT encryption, or a private VPN/WireGuard path.

## NIP-53

The creator dashboard signs a `kind:30311` event containing:

- `d`: internal stream ID
- `title`
- `summary`
- `streaming`: public HLS playlist URL
- `starts`
- `status`: `planned`, `live`, or `ended`
- `p`: creator as `Host`
- `relays`: configured relay hints

Chat messages are signed `kind:1311` events whose `a` tag references `30311:<creator-pubkey>:<stream-id>`.

## XMR tips

The public viewer selects an amount. Live asks Commerce for an internal `live_tip` invoice with that exact atomic-XMR amount. Commerce creates a fresh Monero subaddress. The tip becomes visible in totals only after the configured confirmation count.
